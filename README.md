# 商品住房销售政策裁定

依据项目时态事实裁定商品住房预售、现售及资金监管动作。

## 领域资料

`contracts/domain.schema.json` 记录共享资料结构，`fixtures/domain.json` 是不含真实个人信息的示例。参与方包括住房管理受理人员、房地产开发企业、主办银行、项目复核人员。

当前资料依据以下业务事实维护：

- 新政策按土地公告和许可取得时间区分新项目与在途项目
- 新项目预售要求主体封顶并实施资金全过程监管
- 现房销售、主办银行和按揭放款均有独立前置条件

## 模块结构

- `temporal.py`：土地取得、公告、规划许可、主体封顶、分部验收、预售许可、首次登记、抵押查封、联合验收九类时态事实；带来源、只追加，更正以新事实链接旧事实
- `policy.py`：政策版本簿；分类规则按土地公告、规划许可等事实日期划分新项目与在途项目，版本只增不改
- `ruling.py`：裁定引擎；按有效政策版本判断项目可申请预售、现房备案，或需区政府评估和市级备案，并记录命中的政策日期与所用材料
- `ledger.py`：主办银行项目账本；开发贷、自有资金、预售款、现房定金、受托支付等只追加、不可改写，更正以冲正条目完成
- `service.py`：裁定服务；职责分离、项目版本并发控制、资金动作校验与复核解释

## 业务规则要点

- 开发企业只能提交本项目材料；资金事实由本项目主办银行确认；审批人与材料提交人不得相同
- 定金上限、按揭放款与监管解除必须引用当时资格（最新裁定），资格已更正的引用一律拦截
- 所有变更携带期望项目版本：补证与付款并发时基于同一项目版本串行提交，冲突方重新读取
- 被拒绝的事项不写入账本、不占用额度，但保留处理记录
- 规则更正只产生新裁定并保留旧结论；联合验收前不得解除预售资金监管
- 市级复核经 `review_decision` / `review_project` 抽取任一项目和资金动作，逐项列出命中的政策日期、所用材料、额度变化与拦截原因
